Based on the changes you specified, the **farmer-side flow** should work like this:

## Farmer App Flow

### 1. Farmer Registration / Login

Farmer opens **Mandi Setu Portal** → registers/logs in.

After login, the farmer lands on the farmer dashboard.

---

### 2. Find a Mandi

The farmer goes to:

**Book a Mandi Slot**

The app should show nearby mandis first, sorted by distance.

The farmer can also:

* Search mandi by name
* Search by location
* View mandis on a map
* Filter by available booking slots
* Filter by crops accepted
* View only mandis currently accepting bookings

### What the farmer should see for each Mandi

A mandi card/list item should contain:

* **Mandi name**
* **Distance from farmer**
* **Full address**
* **Pincode**
* **Map/location**
* **Current availability**
* **Available dates**
* **Available time slots**
* **Crops accepted**
* **Rate per KG for each crop**
* **Maximum farmers per slot**
* **Remaining booking capacity**
* **Instructions from mandi**
* Mandi status:

  * Open
  * Closed
  * Fully booked

For example:

> **Pune Agricultural Mandi**
> 8.4 km away
> Pune, Maharashtra – 411001
>
> **Available crops**
>
> * Tomato — ₹24/kg
> * Wheat — ₹28/kg
> * Mustard — ₹52/kg
>
> **Next available:** Tomorrow
> 9:00 AM – 1:30 PM
> 7 slots remaining

---

## 3. Select Mandi

When the farmer opens a mandi, show a **Mandi Details page**.

### Mandi Details

**Basic information**

* Mandi name
* Address
* Pincode
* Map
* Distance
* Open/closed status

**Booking information**

* Available dates
* Available slots
* Remaining capacity
* Expected booking number
* Booking instructions

**Crop information**

| Crop    |   Rate | Available Quantity |
| ------- | -----: | -----------------: |
| Tomato  | ₹24/kg |             100 KG |
| Wheat   | ₹28/kg |             500 KG |
| Mustard | ₹52/kg |             250 KG |

The farmer should **not see internal mandi operational information** such as other farmers' details, internal settlement information, escrow information, etc.

---

# 4. Select Date & Slot

Farmer selects:

**Date → Slot**

For example:

**Monday, 14 September**

* Slot 1 — 9:00 AM–1:30 PM

  * 7 farmers remaining
* Slot 2 — 2:00 PM–4:00 PM

  * 3 farmers remaining

If the mandi has marked that day as **Mandi Closed**, the farmer cannot book it.

If a slot reaches its farmer limit, it should show:

> Fully Booked

and cannot be selected.

---

# 5. Select Crops

The farmer can select **multiple crops in one booking**.

For example:

☑ Tomato — 100 KG
☑ Wheat — 250 KG
☐ Mustard

The farmer enters the quantity in **KG**.

No vehicle-number field should exist anywhere in this flow.

The system should calculate an estimated value:

> Tomato: 100 KG × ₹24 = ₹2,400
> Wheat: 250 KG × ₹28 = ₹7,000
>
> **Estimated total: ₹9,400**

This should be clearly labelled as an **estimated amount**, because the final settlement may depend on the actual weighment/assay.

---

# 6. Booking Request

Before submitting, show a confirmation screen:

### Booking Summary

**Mandi:** Pune Agricultural Mandi
**Date:** 14 September 2026
**Slot:** 9:00 AM – 1:30 PM

**Crops**

* Tomato — 100 KG
* Wheat — 250 KG

**Expected value:** ₹9,400

**Expected booking number:**
For example: `#BKG-1042`

Then:

**Request Booking**

At this point:

### ❌ No QR

### ❌ No token

The farmer has only submitted a **booking request**.

---

# 7. Mandi Reviews Booking

The request appears in the mandi dashboard under:

### Pending Bookings

The mandi user clicks the booking row and sees:

**Farmer details**

* Farmer name
* Contact number
* Farmer ID/profile information

**Booking details**

* Booking number
* Date
* Slot
* Crops
* Quantity of every crop
* Total quantity
* Estimated value
* Any farmer-provided information

The mandi has two options:

### Accept

or

### Reject

If rejecting, **rejection reason is mandatory**.

---

# 8. If Mandi Rejects

Farmer receives a notification:

> Your booking request for Pune Agricultural Mandi on 14 September, 9:00 AM–1:30 PM was rejected.
>
> Reason: Slot capacity exceeded.

The booking becomes:

**Rejected**

The farmer **cannot submit another booking for that same slot**.

They can, however, choose another available slot/date according to the business rules.

No QR or token is generated.

---

# 9. If Mandi Accepts

Once the mandi accepts:

**Booking → Accepted**

The system generates:

* **Token number**
* **QR code**

For example:

> **Token: MND-042**
>
> Monday, 14 September
> 9:00 AM – 1:30 PM
>
> [QR CODE]

The farmer can see this under:

### My Bookings

Booking status:

**Accepted**

The QR/token should only be generated **after mandi approval**.

---

# 10. Farmer Arrives at Mandi

When the selected slot date arrives, the farmer goes to the mandi.

Mandi staff scans the farmer's QR.

The system verifies:

* Booking exists
* Booking belongs to this farmer
* Correct mandi
* Correct date
* Correct slot
* Booking is accepted
* Booking hasn't already been settled/discarded

Then the mandi can proceed with:

**QR Scan → Arrival → Weighment → Crop Settlement**

---

# 11. Settlement

The mandi weighs the actual crops.

For example:

| Crop   | Booked | Actual |
| ------ | -----: | -----: |
| Tomato | 100 KG |  96 KG |
| Wheat  | 250 KG | 243 KG |

The system calculates the final settlement based on actual accepted quantity and applicable rate.

The farmer can then see:

* Actual quantity
* Rate/KG
* Final amount
* Settlement status
* Settlement time
* Booking/token number

## Important distinction in the new flow

The key business rule should be:

**Farmer searches → selects mandi → selects date/slot → selects crops & KG → submits request → mandi approves → token + QR generated → farmer arrives → QR scanned → crops weighed → settlement.**

So **booking request ≠ token**.

A farmer should **never receive a token merely by completing the booking form**. The token is issued only after the mandi accepts the request.

Also, if a mandi is marked **Closed**, it should immediately stop accepting new bookings, and any existing affected bookings should be handled according to your closure policy and reflected in the farmer app.
